What Cookies Achieve

A cookie is a small, client-side key–value record persisted by a user agent across HTTP requests. Formally, let $\mathcal{S}$ denote the set of all possible server states and $\mathcal{C}$ the set of client-side name–value pairs with associated metadata $(d, p, e)$ — domain $d$, path $p$, and expiry $e \in \mathbb{R}_{>0} \cup \{\infty\}$. A cookie $c \in \mathcal{C}$ acts as a state-projection function:

$$\phi : \mathcal{S} \times \mathcal{C} \to \mathcal{S}, \quad \phi(s, c) = s'$$

mapping a stateless exchange $(s, c)$ back onto a stateful continuation $s'$. This is the natural endpoint of the book's arc: we began with discrete key–value stores, introduced hashing and collision resolution, then studied expiry policies modelled by exponential decay $v(t) = v_0 e^{-\lambda t}$. Cookies unify all three threads — storage, lookup, and lifetime — into one deployable primitive.

Worked Example

Consider a shopping cart session. A server issues the header

Set-Cookie: cart_id=a3f9; Max-Age=3600; Path=/; HttpOnly

The identifier cart_id is the hash key; a3f9 is a collision-resistant digest of the user's session entropy; Max-Age=3600 encodes the decay half-life $T_{1/2} = 3600\,\text{s}$. On the next request the browser returns the cookie, and the server retrieves the cart state in $O(1)$ average time via the underlying hash table.

Key Theorem

Theorem (Session Identifiability). If cookie identifiers are drawn uniformly from a space of size $N$ and $k$ sessions are active simultaneously, the probability of at least one collision satisfies

$$P(\text{collision}) \leq 1 - e^{-k(k-1)/(2N)}.$$

For $N = 2^{128}$ this probability remains negligible even for $k = 10^{9}$, justifying the use of 128-bit tokens in production systems.

Lab Cell

from sympy import symbols, exp, solve, simplify

t, lam, v0 = symbols('t lambda v_0', positive=True)
v = v0 * exp(-lam * t)
half_life = solve(v - v0/2, t)[0]
print("Half-life T_{1/2} =", simplify(half_life))

Running this cell confirms $T_{1/2} = \ln 2 / \lambda$, the formula governing every Max-Age policy discussed in this chapter.

The machinery developed here — hashing, expiry, and stateful projection — extends far beyond session management.
