Random Forest

You already know that a single decision tree asks a sequence of yes/no questions to reach a prediction. The problem? One tree can memorize the training data too closely — it nails the examples it has seen but stumbles on new ones. The fix is surprisingly intuitive: ask many trees, then take a vote.

Building the forest. A random forest grows $T$ decision trees (often $T = 100$ or more), but with two deliberate doses of randomness injected at training time:

  • Bootstrap sampling — each tree trains on a random sample of the original dataset, drawn with replacement (so some rows appear twice, others not at all). If the full dataset has $n$ examples, each tree still sees roughly $n$ rows, but a different mix.
  • Feature subsampling — at every split inside a tree, only a random subset of $m$ features is considered (a common choice is $m = \lfloor \sqrt{p} \rfloor$ where $p$ is the total number of features).

    • These two steps mean each tree learns a slightly different version of the truth. At prediction time, every tree casts a vote for a class label, and the forest returns the majority vote:

    $$\hat{y} = \text{mode}\bigl(\hat{y}_1,\, \hat{y}_2,\, \ldots,\, \hat{y}_T\bigr)$$

    Because errors made by individual trees are largely uncorrelated — different trees trip on different examples — they tend to cancel out in the vote rather than pile up.

    The key pattern. More diverse trees → more errors cancel → stronger ensemble. Randomness is not a weakness; it is the source of diversity that makes the forest more reliable than any single tree.

    Practice problem. Suppose you have $p = 9$ features in your dataset. A random forest uses $m = \lfloor \sqrt{9} \rfloor$ features at each split. If 7 out of 10 trees predict class A and 3 predict class B, what does the forest predict, and how many features does each split consider?
