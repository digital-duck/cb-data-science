Binary Multiclass Classification

You already know the core idea: a classifier looks at input data and makes a decision. A binary classifier chooses between exactly two outcomes — spam or not spam, pass or fail, cat or not cat. That two-way split is clean and powerful, but most real problems have more than two possible answers.

Multiclass classification handles $k > 2$ categories. Instead of one decision boundary splitting the world in half, the model now draws multiple boundaries — imagine carving a map into several regions, one per class. A classic example: given a handwritten digit image, predict which of $\{0, 1, 2, \ldots, 9\}$ it is. That's 10 classes.

One widely-used strategy is called One-vs-Rest (OvR). For each class $c_i$, you train a separate binary classifier:

$$f_i(\mathbf{x}) = \begin{cases} 1 & \text{if } \mathbf{x} \text{ belongs to class } c_i \\ 0 & \text{otherwise} \end{cases}$$

You run all $k$ classifiers on a new input and pick the one with the highest confidence score. If you have 4 classes, you train 4 binary classifiers — one per class against all others.

Another approach, used in neural networks, applies the softmax function to produce a probability for each class:

$$P(y = c_i \mid \mathbf{x}) = \frac{e^{z_i}}{\sum_{j=1}^{k} e^{z_j}}$$

All probabilities sum to 1, and the predicted class is $\arg\max_i P(y = c_i \mid \mathbf{x})$.

The pattern: binary classification is the special case $k = 2$; multiclass generalizes it by either training multiple binary models or computing class probabilities jointly.

Practice problem: You are classifying fruit images into three categories: apple, banana, or orange. Using the One-vs-Rest strategy, how many binary classifiers would you need to train? Describe in one sentence what each classifier's "positive class" would be.
