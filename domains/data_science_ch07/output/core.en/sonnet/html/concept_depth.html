Depth

You already sense what depth means: it's how far down something sits. A grandfather is closer to the top of a family tree than a grandchild. The CEO is one level from the root of an org chart; a junior analyst might be four levels down. That everyday intuition is exactly right — now let's sharpen it into something you can calculate.

In a tree (a connected graph with no cycles), every node has a precise depth. We define it recursively:

  • The root has depth $0$.
  • Every other node has depth equal to its parent's depth plus one.

    • So if node $A$ is the root and $B$ is $A$'s child, then $\text{depth}(B) = 1$. If $C$ is $B$'s child, $\text{depth}(C) = 2$, and so on. Formally:

    $$\text{depth}(v) = \begin{cases} 0 & \text{if } v \text{ is the root} \\ \text{depth}(\text{parent}(v)) + 1 & \text{otherwise} \end{cases}$$

    This recursive rule is powerful because it works on trees of any shape — balanced or lopsided, wide or narrow.

    One key pattern: the height of a tree is the maximum depth among all its leaves. A tree with height $h$ can have at most $2^{h+1} - 1$ nodes if it's a perfect binary tree. Depth tells you about a single node; height summarizes the whole tree.
